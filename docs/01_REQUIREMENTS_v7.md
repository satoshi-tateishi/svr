# REQUIREMENTS_v7.md（人員・配車統合確定版）

## 1. プロジェクト目的

### 最優先

管理負荷を減らす（人員配置・配車・工程管理の一元化）

### 次点

-   手配ミス（ダブルブッキング・漏れ）をなくす
-   情報共有を楽にする（希望時間と確定時間の可視化）

### 優先度低

-   経営データ可視化

* * *

## 2. システム全体アーキテクチャ

### 自作アプリ（Django / Docker）

-   人員手配申請 / 配車工程申請（Request）
-   実績確定（Assignment / Operation）
-   **ダブルブッキング防止（人員・車輌双方の占有時間管理）**
-   ポジション管理
-   案件別単価管理（期間対応・履歴保持）
-   🔒 Lock時単価・原価スナップショット確定
-   手当登録管理
-   SaaS連携制御（freee / board）

### 通知 / SaaS連携

-   LINE WORKS API連携
-   freee人事労務（社員給与・外注支払）
-   board（外注請求・案件売上管理）

* * *

## 3. 責務の境界（厳守）

自作アプリは「確定実績」までを責務とする。金額の最終法的確定はSaaS側。
ただし、**🔒 Lock時点の適用単価・手当合計・配車原価は自作アプリが確定責任を持つ。**

* * *

## 4. 設計原則（絶対遵守）

1.  公演担当者主導型
2.  Request（希望） / Assignment（割当） 分離
3.  占有時間はバッファ込み（人員・車輌共通）
4.  物理削除禁止 / 破壊的変更禁止
5.  ロール混同禁止 / SaaS責務侵害禁止
6.  金額ロジックをSaaSと競合させない
7.  単価は履歴保持（上書き禁止）
8.  **🔒 Lock後は金額・工程・ポジションの再計算・変更禁止**
9.  **🔒 Lock時点で全ての金額要素をスナップショット保存する**
10.  **申請時間と確定時間を別保持し、比較可能にする**

* * *

## 5. 単価・原価設計

### 人員（PerformanceFreelanceRate）

-   user × position × 期間 で一意。
-   Lock時に `StaffAssignment` へスナップショット保存。

### 車輌（Vehicle / VehicleCost）

-   **車輌区分**: 自社トラック、個人所有車（スタッフ自家用）、外注トラック。
-   **原価構造**:
    
    -   自社車輌でも外注ドライバー時は費用発生。
    -   外注費は「1日単位」または「距離変動」があるため、Lock時に管理者が最終額を確定入力する。
-   **売上構造**: 案件ごとの「運行工程（Operation）数」に基づき計算。

* * *

## 6. 配車・工程管理（新規追加）

### 6.1 運行工程（VehicleOperation）

1案件につき複数の工程を紐付け管理する。

-   `request_time`: 申請者の希望時間
-   `scheduled_time`: 管理者の確定時間
-   `route_from` / `route_to`: 発着地
-   `description`: 荷積、搬入、引き取り等の内容

### 6.2 車輌割当（VehicleAssignment）

-   1つの工程に1つの車輌を割り当て。
-   同一車輌が別案件の工程を連続して担当可能（占有時間の重複は不可）。
-   外注車輌の場合、個体（登録番号等）を特定してアサイン。

* * *

## 7. 🔒 Lock時スナップショット設計

### 7.1 StaffAssignment（人員）

Lock時に保存：

-   `applied_unit_price` / `applied_allowance_total` / `applied_total_amount`
-   `applied_position_name` / `locked_at`

### 7.2 VehicleAssignment（配車）

Lock時に保存：

-   `applied_cost_amount`: 外注費・ドライバー費等の確定原価
-   `applied_sales_amount`: 案件側への請求用金額（工程数等から算出）
-   `actual_operation_count`: 確定時の工程数
-   `locked_at`

* * *

## 8. ワークフロー（配車含）

1.  マスタ登録（人員単価・車輌）
2.  **Request**: 制作が「人員」と「配車工程（希望時間込）」を申請
3.  **Assignment**: 管理者が「人員」と「実車輌」を割り当て、時間を確定
4.  **Costing**: 外注費等の変動原価を入力
5.  **🔒 Lock**: 全ての金額・時間をスナップショット保存
6.  **Data Export**: SaaS（freee / board）へ送信

* * *

## 9. やらないことリスト

1.  単価・工程履歴の上書き
2.  Lock後の金額・ポジション・工程内容の変更
3.  SaaS側で行うべき複雑な税計算・社会保険計算の内製化
4.  車輌のリアルタイムGPS追跡（本システムのスコープ外）

* * *

## 10. 非機能要件

-   Ubuntu 24.04 / Django / Docker / MySQL
-   LINE WORKS SSO
-   **Lock処理はトランザクション管理（atomic / select_for_update）必須**
-   AuditLog（監査ログ）によるLockイベントの記録

* * *

# 11. AI実装時の厳守事項（更新）

- Lock処理はatomicトランザクション必須
- select_for_update利用
- 単価履歴期間重複禁止制約をDBレベルで実装
- スナップショット保存を必須実装
- 再計算ロジックを持たない
- AuditLogでLockイベント記録

* * *

# 12. 設計思想の最終確定

- 金額はLock時に確定する
- 確定後は変更しない
- SaaSは最終会計責任
- 自作アプリは確定実績責任
- 巻き戻ししない
- 過去を書き換えない

これを絶対原則とする。
