# PERMISSION_DESIGN_v3.md

## 公演手配管理システム 権限設計書（人員・配車・スナップショット統合版）

* * *

# 1. 設計思想

本システムは、**システムロール（全体）**と**公演内ロール（案件単位）**の二層構造で制御する。 特に「金額（単価・原価・請求額）」は極めて高い機密性を持たせ、現場責任者（Chief）であっても閲覧を制限する。

-   **View層**: UIの表示/非表示制御（一次判定）
-   **Service層**: ロジック実行直前の最終判定（二次判定・防衛）
-   **状態制御**: `Locked` 状態のレコードに対する破壊的変更を全ロールで禁止する。

# 2. ロール定義（更新）

### 2.1 システムロール（システム全体の権限）

| Role | 説明  |
| --- | --- |
| **Admin** | 全権限（Lock解除、API再送、監査ログ閲覧、マスタ管理） |
| **Editor** | 横断編集者（全案件の編集・単価登録が可能。Lock解除は不可） |

# 4. 金額閲覧制御（機密性保持）

スナップショット保存された以下の項目は、`Admin / Editor / Planner` 以外にはレスポンスを返さない。

-   `StaffAssignment.applied_unit_price`（単価）
-   `StaffAssignment.applied_total_amount`（総額）
-   `VehicleAssignment.applied_cost_amount`（外注原価）
-   `VehicleAssignment.applied_sales_amount`（売上/請求額）

* * *

# 5. 🔒 Locked状態による制限（不変性）

ステータスが `Locked` に遷移した後は、**Adminであっても** 以下の操作をService層で遮断する。

1.  **人員**: メンバー変更、ポジション変更、手当の追加/削除、単価の再計算
2.  **配車**: 車輌の変更、運行時間の変更、ルートの変更、原価の再入力
3.  **共通**: 占有時間（Occupied Time）に影響する変更

* * *

# 6. Lock解除ポリシー

-   **原則**: Lock解除機能は一般UIに実装しない。
-   **Adminのみ**: データベース直接操作と同等の慎重さで、管理画面の奥深くからのみ実行可能。
-   **制約**: API送信済（ログあり）の場合は、送信先SaaSとの不整合を警告する。

* * *

# 7. 監査ログ(AuditLog)対象操作

以下の操作は、誰がいつ行ったかをすべて記録し、削除不能とする。

-   **単価関連**: 単価の新規登録、期間変更
-   **配車関連**: 外注原価の最終入力、時間の確定
-   **確定関連**: 🔒 Lockの実行、AdminによるLock強制解除
-   **API関連**: 送信失敗時の手動再送実行

# 9. 禁止事項

1.  **金額をフロントエンドで隠すだけ**: 必ずAPIレスポンスの段階で、ロールに応じてフィールドを `null` 化または除外すること。
2.  **Chiefによる原価入力**: 原価（外注費）はPlanner以上が入力するか、マスタから自動計算されたものをPlannerが承認（Lock）するフローを死守する。
3.  **将来的な権限昇格の放置**: 現場スタッフが案件ごとにPlanner権限を安易に持てないよう、任命プロセスを明確にする。
